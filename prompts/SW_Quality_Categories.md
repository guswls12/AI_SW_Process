# SW 품질 결함 카테고리 기준 — 단순/복합 6개 카테고리 + 20개 유형

> **목적**: 차량용 임베디드 SW 코드 리뷰에서 사용하는 단순/복합 결함 분류 기준.
> **단순 오류**: cat1 (최초 구현 미흡), cat2 (변경점 관리 미흡)
> **복합 오류**: cat3 (요구사양 분석/검증 미흡), cat4 (시스템 설계/검증 미흡),
>               cat5 (아키텍처 설계/검증 미흡), cat6 (상세 설계/검증 미흡)

---

**카테고리 1 (단순): 최초 구현 미흡 [유형 1~3]**
- 유형 1 - 로직 구현 오류: 올바르게 설계된 로직이나 알고리즘을 실제 코드로 구현시 조건문, 계산식 등 단순 오구현
  상세 예시:
  - 초기화되지 않은 구조체 변수 사용으로 인한 부팅 불가
  - X축 값을 Y축 값으로 사용하여 오경보 발생
  - 6이상 값일 때 로직 실행되어야 하나 6 초과로 코딩되어 로직 작동 불가
  - 편차 연산 시 목표값과 현재값으로 연산해야 하나 목표값과 과거값으로 연산하여 로직 작동 불가
- 유형 2 - 파라미터 관리 미흡: Variant/옵션/사양별 파라미터, 구성 파일 등 s/w가 제대로 작동하는데 필요한 설정 정보를 잘못 관리하여 발생된 문제
  상세 예시:
  - EU 사양 베리언트 코드 분리하지 않아 기본값인 국내 사양으로 동작
  - 베리언트 코드 값 미반영으로 기본 사양으로 동작
  - 터키 튜닝 값을 러시아/호주 사양에 적용
  - 캘리브레이션 동작 시 +로 보정해야 하나 -로 보정하여 오작동 발생
- 유형 3 - 기능 누락: 단순 실수로 변경점 오반영 누락
  상세 예시:
  - 고장 진단 수행 후 사용자 알람을 위한 인터페이스 기능 구현 누락
  - 고장 FLAG 발생 후 회복 시 과거 고장 FLAG 초기화 기능 누락으로 경고등 점등
  - 인증 실패/성공 판단 기능 누락으로 DTC 미해제
  - 기능 비활성화 조건 진입 시 경고음 해제 로직 누락

---

**카테고리 2 (단순): 변경점 관리 미흡 [유형 4~6]**
- 유형 4 - 변경점 반영 미흡 : 단순 실수로 변경점 오반영/누락
  상세 예시:
  - A사양 스케일 14단계, B사양 32단계로 변경 CR 확인했지만 모두 14단계로 반영
  - 메시지 신호 추가로 CRC 계산 방식 변경되어야 하나 기존 방법 사용으로 제어기 동작 불가
  - 소자 변경으로 과전류 인식값 변경 필요했으나 기존 값 사용으로 Fail-Safe 로직 동작 불가
  - CR 발생 시 기존 기능 삭제 요청했지만 실제 코드에 미반영되어 오동작 발생
- 유형 5 - S/W 변경 영향도 분석 미흡 : S/W 기능 등 변경되었으나, 변경과 연계된 다른 기능/모듈의 영향성 검토 미흡
  상세 예시:
  - MCU 소자 변경 이후 로직간 매칭성 결함 (MCU 아키텍처 상이로 L-CAN 인터럽트 처리 불가)
  - CAN 신호명 변경 시 영향받는 타 제어기 영향성 검토 미흡
  - ECUNAME 배열 크기 조절 후 CAN 송출 설정 유지로 무효한 값 추가 송출
  - SWP 변경(UNECE 적용) 시 CAN 신호 송출 타이밍 초기값 오설정
- 유형 6 - 버전/코드 관리 미흡: S/W 버전 관리 체계 또는 코드 병합/릴리즈 관리 오류로 인해 잘못된 코드가 적용된 문제
  상세 예시:
  - 개발 단계 시 제어기 S/W 구버전 오적용
  - S/W 반영 서버 내 개발버전/배포버전 분리 안되어 배포용 서버에 개발 중인 S/W 오반영
  - 신규 신호 반영 수평 전개 시 특정 MY 브랜치에 미적용
  - S/W 코드 구분 관리 미흡으로 구버전에 신규 사양 오적용

---

**카테고리 3 (복합): 요구사양 분석/검증 미흡 [유형 7]**
- 유형 7 - 요구 사양 미확인/오해석: 요구사양 분석시 이해부족으로 설계 오반영/누락 또는 요구 사양 변경시 명확히 반영하지 않거나 관리하지 않아서 발생한 문제
  상세 예시:
  - 사양서 국문→영문 번역 시 오번역으로 로직 구현 오류
  - CAN 강제 슬립 조건 오해석으로 미반영
  - 옵션 구성표 기반 설계 시 사양별 베리언트 코딩 오해석으로 오적용
  - HMC 기술 표준 임의 해석으로 HEV용 CAN 신호명 오설정
  요구사항이 제공된 경우 모든 조건(전처리/후처리)이 코드에 구현됐는지 대조할 것.

---

**카테고리 4 (복합): 시스템 설계/검증 미흡 [유형 8~11]**
- 유형 8 - 시스템 Reset 로직 설계 미흡 : 통신 실패 등 시스템 이상 상태에서 예방/복구 로직 설계 미흡 또는 시스템 오류에 대한 근본 원인 분석이 안되어 Reset 로직 적용
  상세 예시:
  - ECC 발생 시 FBL에서 필수 읽기 동작 필요한 참조 영역이면 ECC Skip 해야 하나 상시 Reset
  - MCU Task Stuck 시 Reset 로직 반영 미흡
  - 간헐적 LIN/CAN 통신 Tx 불가 시 Reset 로직 반영 미흡
  - GPIO Low 상태에서 제어기 부팅 오류 발생 시 Reset 등 Fail-safe 반영 미흡
- 유형 9 - 모듈간 연계 고려 미흡 : 모듈간 통신(I2C/SPI 등) 및 연계 제어 로직 고려 설계 미흡
  상세 예시:
  - I2C 통신 안정화 시간 고려 미흡으로 비정상 통신 상태 시 강건 설계 미흡
  - SPI 통신으로 DATA READ 중 노이즈 유입으로 DATA 왜곡 발생
  - 소자간 초기 통신 동기화 시 샘플링 포인트 불일치
  - 단품 산포 고려한 로직 설계 미흡 (Cal 안정화 시간, 펄스 판단 안정화 시간, 잔여 기전력에 의한 홀센서 틀어짐 등)
- 유형 10 - 제어기 간 연계 고려 미흡 : 제어기간 통신(CAN, LIN등) 및 연계 제어 로직 고려 설계 미흡
  상세 예시:
  - B-CAN 버스 로드 과다에 의한 송신 메시지 누락
  - 제어기간 CAN 메시지 송출 및 진단 방식 불일치
  - 제어기간 시동(IGN) 전원 필터링 시간 차이로 무전원 구간 발생하여 기능 비정상 종료
  - 상위 제어기와 메시지 처리 방식 상이로 기능 오동작
- 유형 11 - 시스템 예외 감지 미흡: 시스템 모니터링 기능이 없어서 오류 발생
  상세 예시:
  - MCU 부팅 이후 AP 상태 모니터링 기능이 없어서 오동작 시 복구 불가
  - eMMC 내 data 에러 검출(패리티 체크) 로직이 없어서 오염 데이터 저장
  - All app shutdown 미응답 모니터링 및 Fail-Safe 부재
  - 저전압 상태 감지 로직이 없어서 저전압 시스템 방전

**카테고리 5 (복합): 아키텍처 설계/검증 미흡 [유형 12~16]**
- 유형 12 - 메모리 관리 미흡 : 메모리 접근 로직(R/W) 설계 미흡
  상세 예시:
  - 비정상 전원(저장 중 리셋, 저전압, 전원 순단 등) 조건에서 Fail-Safe 설계 미흡으로 메모리/파일 시스템 R/W 오류
  - EEPROM 쓰기 중 로직 충돌로 무한루프 진입 시 Fail-Safe 부재
  - 로그 누적 저장이 되지 않아야 하나 누적 저장되어 저장 용량 초과
  - 간헐적으로 파일이 비정상적으로 생성(File Size: 0)되는 경우 Fail-Safe 부재
- 유형 13 - 동작 우선순위 설계 오류 : 기능 동작 순서가 잘못 설계되어 발생한 오류
  상세 예시:
  - 우선순위가 높은 Task보다 낮은 우선순위 Task가 우선 실행되어 고장 코드 발생
  - 슬립 진입 시 간헐적 통신 모드 전환(FULL_COM→SILENT_COM→NO_COM) 지연으로 통신/ECU 모드 불일치
  - Data Flash Writing 진행 중 Writing 완료되지 않은 상태에서 Sleep 명령 실행되어 Shutdown 모드 오진입
  - Sleep에서 Wake-Up 후 SWP의 CAN-Tx 준비 상태에서 전송하여 SWP에서 처리 못함
- 유형 14 - 인터럽트 설계 오류 : 인터럽트 발생 조건, 처리 순서, 복귀 시점 등 인터럽트 처리 루틴에 대한 설계/검증 미흡
  상세 예시:
  - 슬립 진입 시 외부 인터럽트(CAN 신호)와 MCU 내부 인터럽트 모두 종료 후 슬립 진입해야 하나 외부만 종료하고 진입하여 Wake-Up 시 간헐적 MCU 미작동
  - 인터럽트 Clear 중복 처리(2회)로 무효 인터럽트 발생하여 플랫폼 S/W Task 순서 제어 오류
  - 슬립 준비 완료 전 10ms 이내 인터럽트 발생 시 즉시 처리하여 슬립 미진입
  - 기능 동작 중 특정 타이밍에 타기능 동작에 의한 인터럽트 시 작동 불가
- 유형 15 - 응답시간 설계 오류 : 기능 처리시간 고려 미흡(로직 Delay 고려 설계 미흡 등)
  상세 예시:
  - IGN OFF 이후 B+모드 종료 후 종료 대기 모드 이내 IGN ON 시 CAN 메시지 지연 송출 고려 설계 미흡
  - NAND Flash 데이터 스캔 시간 증가로 그래픽 메모리(RAM) 초기화 지연되어 Watchdog Timeout 발생
  - 부팅 과정 중 간헐적으로 센서 신호 수집/처리 기능(ADC, DMA) 활성화 지연으로 처리 실패
  - 시동 초기 수신 소자 준비 완료 전 송신 소자 먼저 연결 시도 시 간헐적 연결 지연으로 화면 미표출
- 유형 16 - 공유자원 설계 오류 : 메모리 변수, Task 등 공유 자원에 대한 임계영역 설계/검증 미흡
  상세 예시:
  - 시스템 간 워치독 타이머 설정 고려 미흡하여 상호 간섭 발생 및 시스템 지속 리셋
  - 인터럽트 관리 변수에 서로 다른 Core가 동시 접근하여 중복 처리 (Spinlock 메커니즘 미적용)
  - 멀티스레드 환경에서 공유 자원에 대한 동시성 보장 미흡 (Mutex 미적용)
  - NVM 접근 후 Unlock 처리를 누락하여 다른 Task와 충돌

**카테고리 6 (복합): 상세 설계/검증 미흡 [유형 17~20]**
- 유형 17 - 환경 조건 고려 미흡 : 외부 물리적 환경(온도/전압 등)에 대한 시스템 동작 조건 등 고려 설계 미흡
  상세 예시:
  - 시동 시 배터리 전압 강하 조건 반영 미흡하여 DTC 민감 검출
  - 바람 등에 의한 차량의 미세 움직임을 아기 호흡으로 오감지 (물체 감지 로직 민감)
  - 급격한 환경 변화(온도 충격 등)에 의한 비정상 주파수 표출로 캘리브레이션 로직 오류
  - PMIC 노이즈로 인한 AP 내부 온도값 오센싱 시 Thermal Mitigation 동작으로 기능 동작 지연
- 유형 18 - 임계값 설계 미흡: 센서 등 입출력 범위 및 민감도(임계값) 고려 설계 미흡
  상세 예시:
  - 지면 노이즈 필터 조건 민감설계로 지면 신호를 사물로 오판단
  - 제어기/스위치 개별 표준 저항 오차 고려 설정했으나 MIN 값의 여유도 부족
  - DTC 점등 판단을 위한 내부 보정 기준값 초과 조건(1회) 민감 설정으로 DTC 민감 검출
  - 무선 주파수 감지 로직 설계 미흡으로 변동 감지 민감도가 높아 차량 내부 노이즈 주파수 오감지
- 유형 19 - 예외 입력/신호 처리 미흡: 입력 신호 상태 처리에 대한 처리 로직 설계 미흡(Invalid 및 비정상 신호 등)
  상세 예시:
  - Invalid 값 수신 시 Last value 유지토록 예외 처리 설계 미흡
  - Data Length 100바이트 초과 시 무효 처리해야 하나 오설계로 메모리 오버라이팅
  - 비정상 데이터 수신 시 데이터 정합성 판단(데이터 길이 등)하여 처리토록 예외 처리 설계 미흡
  - A 시그널 유효값 수신 시 B 시그널 값과 무관하게 메뉴 표시되어야 하나 신호 처리 미흡
- 유형 20 - 로직 에러 흐름 고려 미흡: 정상 흐름 외에 S/W에서 발생 가능한 오류 및 예외 상황에서 예방 및 복구 로직 설계 미흡
  상세 예시:
  - 연속 동일 Wake Up SMS 메시지 처리 케이스에 대한 예외 로직 설계 미흡
