## 🔬 정적 분석 위반

> 선택된 코딩 표준({standards}) 기준으로 검출된 정적 분석 위반 항목.
> H/M/L SW 품질 결함과 독립된 섹션이며, 위반이 없으면 "선택된 코딩 표준 내 정적 분석 위반 없음 — 검토 완료"로 표기.
>
> **항목별 헤딩 필수 (반드시 준수):**
> - 모든 SA 항목은 `### SA-N. [규칙 분류] [위반 항목 제목] — [규칙 ID]` 형식의
>   **개별 헤딩**으로 시작한다.
> - 여러 SA 항목을 하나의 요약 표(예: ID/위치/규칙/위반내용/관련SW결함 5컬럼 표)로
>   합쳐 출력하는 것은 절대 금지한다 — UI 사이드바가 헤딩 단위로 항목을 식별하므로
>   요약 표만 있으면 사용자에게 항목이 표시되지 않는다.
>
> **출력 분기 (반드시 준수):**
> - "관련 SW 결함" 컬럼이 H-N/M-N/L-N 인 경우 → SA-N 헤딩 + 항목/내용 표 +
>   "📎 상세는 [H-N] 참조" 한 줄로 끝.
>   위반 코드/위반 내용/수정 방법 등 상세 섹션 전체 생략.
> - "관련 SW 결함" 컬럼이 "—" 인 경우 → SA-N 헤딩 + 항목/내용 표 + 아래 위반 코드/
>   내용/수정 방법까지 모두 작성.
>
> **규칙 ID 표기 형식 (반드시 준수 — 가독성):**
> - 규칙 ID 는 항상 백틱으로 감싼다: `` `Rule 9.1` ``, `` `EXP33-C` `` (코드 배지로 렌더됨).
> - 표준명은 짧은 대괄호 태그로 ID 앞에 둔다: `[MISRA-C:2012]`, `[MISRA-C:2023]`, `[CERT-C]`.
> - 한 셀에 규칙이 여러 개면 슬래시(/) 로 잇지 말고 공백 하나로 나열한다.
>   렌더러가 두 번째 표준 태그부터 자동으로 줄바꿈하므로 셀 안에서 한 규칙씩 보인다.
>   * 좋은 예: `` [MISRA-C:2012] `Rule 9.1` [CERT-C] `EXP33-C` ``
>   * 좋은 예: `` [MISRA-C:2012] `Rule 12.1` [MISRA-C:2012] `Rule 11.3` ``
>   * 나쁜 예: `MISRA-C:2012 Rule 9.1 / CERT-C EXP33-C` (slash·prefix 반복)
