# 🔍 코드 취약점 분석 리포트

## 📊 분석 요약

> ⚠️ **이 분석 요약 표는 전체 리포트 맨 상단에 단 한 번만 출력한다.**
> 변경점 그룹별 / 매칭 그룹별 / "미매칭 된 항목들" 섹션 안에서 다시 출력하지 말 것.
> 아래 표의 N 건수는 리포트 전체 (모든 변경점 + 미매칭 포함) 의 결함을 모두 합산한 총계이다.

{sa_summary_note}

| 심각도 | 건수 | 유형 분류 |
|--------|------|-----------|
| 🔴 High   | N건 | 단순 오류 N건, 복합 오류 N건 |
| 🟡 Middle | N건 | 단순 오류 N건, 복합 오류 N건 |
| 🟢 Low    | N건 | 단순 오류 N건, 복합 오류 N건 |
| **합계**  | **N건** | **단순 오류 N건, 복합 오류 N건** |

**유형 분류 작성 규칙 (반드시 준수):**
- "유형 분류" 컬럼에는 해당 심각도 내 결함을 **`단순 오류 N건, 복합 오류 N건`** 형식으로 집계한다.
- **단순/복합 매핑 기준:**
  * **단순 오류** = cat1 (최초 구현 미흡), cat2 (변경점 관리 미흡)
  * **복합 오류** = cat3 (요구사양 분석/검증 미흡), cat4 (시스템 설계/검증 미흡),
    cat5 (아키텍처 설계/검증 미흡), cat6 (상세 설계/검증 미흡)
  * **카테고리별 상세 정의** (유형 + 상세 예시) 는 입력된 `=== SW 품질 결함 카테고리 기준 ===` 섹션 참조.
- 각 심각도 행의 `단순 N건 + 복합 N건` 합은 같은 행의 `건수`와 일치해야 한다.
- **합계 행**: 모든 심각도(H/M/L)의 단순/복합 건수를 각각 합산한 총합을 굵게(`**...**`) 표기.
- 해당 심각도에 결함이 0건이면 `—` 로 표기한다.
- 단순·복합 모두 0건인 심각도가 있으면 `0건이 있는 항목은 생략` 가능 (예: `복합 오류 2건` 만 표기).

> 결함이 전혀 발견되지 않은 경우: "분석 대상 코딩 표준 내 결함 없음 — 코드 검토 완료"로만 표기하고 이하 섹션 전체 생략.
